Technical Stack for "Spider-Sense" — Full Project

The complete framework/tool breakdown, organized by the same phases as the roadmap.

1. Language & Core Environment
Python 3.10+ — primary language for ML/NLP pipeline
JavaScript/TypeScript — frontend + browser extension
Jupyter Notebooks — experimentation, EDA, model prototyping before productionizing
2. Data Collection & Processing
Pandas / NumPy — dataset wrangling, feature tables
BeautifulSoup4 / newspaper3k / trafilatura — scraping and clean article-text extraction from URLs
Datasets (HuggingFace) — loading public human/AI text corpora (e.g. HC3, GPT-2 Output Dataset, TweepFake)
OpenAI API / Anthropic API / Cohere API — generating matching AI-text samples across topics for balanced dataset creation
NLTK / spaCy — tokenization, POS tagging, sentence segmentation (needed for stylometric features)
3. Feature Engineering
spaCy — POS distributions, syntactic features
textstat — readability scores, sentence-length variance, lexical density
scikit-learn — TF-IDF, feature scaling/normalization, classical ML pipeline utilities
Sentence-Transformers (SBERT) — semantic embeddings as classifier input
4. Perplexity/DetectGPT-Style Module (training-free detector)
HuggingFace Transformers — loading a small reference LM (GPT-2, GPT-Neo, or Pythia) to compute token-level log-probabilities
PyTorch — backend for running the reference LM and any custom perturbation logic
GPTZero-style open implementations (e.g. detectgpt, fast-detect-gpt open-source repos) — reference implementation to adapt rather than build perplexity/curvature scoring from scratch
5. Supervised Classifier (transformer fine-tuning)
HuggingFace Transformers + Trainer API — fine-tuning DistilBERT/RoBERTa-base for binary classification
PyTorch (or TensorFlow/Keras, pick one — Transformers supports both, but PyTorch is the more common path)
HuggingFace Accelerate — if GPU training needs multi-device/mixed-precision handling
Weights & Biases (wandb) (optional) — experiment tracking across model runs
6. Ensemble & Calibration
scikit-learn — meta-classifier (logistic regression), Platt scaling/isotonic regression for probability calibration
XGBoost / LightGBM — for the stylometric baseline and/or ensemble meta-learner
7. Explainability Layer
SHAP or LIME — feature-attribution for the classical/ensemble model
Captum (if deeper transformer attention explanation is needed) — token-level attribution for the transformer classifier
Custom per-sentence perplexity scoring — reused from the DetectGPT module for "evidence highlighting" in UI
8. Backend / API
FastAPI — REST API layer (async, fast, auto-generates OpenAPI docs) — preferred over Flask for this use case
Uvicorn — ASGI server to run FastAPI
Pydantic — request/response schema validation
Redis — caching repeated text-hash lookups, rate limiting
Celery (optional, if async job queue needed for heavy perplexity computation)
9. Model Serving/Optimization
ONNX Runtime or TorchScript — optimize transformer inference latency for near real-time response
HuggingFace Optimum (optional) — quantization for faster CPU inference if no GPU in deployment
10. Frontend
React (with Vite or Next.js) — main web app
Tailwind CSS — styling ("Spider-Sense tingle meter" UI, gauges, highlight overlays)
Recharts / D3.js — rendering the confidence gauge and evidence visualizations
Axios / Fetch API — calling the backend
11. Browser Extension (stretch feature)
Chrome Extension Manifest V3 — extension scaffold
Vanilla JS or React (via CRXJS/Vite plugin) — extension popup/content-script UI
Content script uses the same FastAPI backend endpoint
12. Deployment & Infra
Docker — containerize backend
Render / Railway / Fly.io — quick-deploy hosting for hackathon timelines (alternative: AWS/GCP if more time/credits available)
Vercel / Netlify — frontend static hosting
GitHub Actions — CI/CD (lint, test, auto-deploy on push)
13. Testing & Evaluation
pytest — backend/unit testing
scikit-learn metrics — accuracy/F1/ROC-AUC reporting
Locust (optional) — load/latency testing of the API before demo day
